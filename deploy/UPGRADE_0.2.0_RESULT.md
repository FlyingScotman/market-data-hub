## Причина промежуточного сбоя и исправление

Установка 0.1.7 (заявка №1) остановилась в staging: старый updater не содержал Buildx,
Compose перешёл к classic builder, не поддерживающему Dockerfile `RUN --mount`.
Drain/миграции/переключение не начинались, production продолжал работать на 0.1.3.
Подписанный 0.1.7 помечен prerelease; архив и запись ошибки сохранены для аудита.

Для первого перехода в работающий контейнер старого updater установлен только штатный
`docker-buildx-plugin`; код mdhub 0.1.3 не изменялся. Реальная пробная BuildKit-сборка с cache
mount прошла. Постоянная правка `1a6cf7f` добавляет Buildx в Dockerfile и проверяет его запуск
во время сборки. 20 deploy-тестов прошли. Исправление выпущено в 0.1.8 и входит в 0.2.0;
промежуточный 0.1.8 на production не устанавливался. В новом updater проверен Buildx 0.38.1.
Причина устранена, дополнительных действий для этого сбоя не осталось.

## Границы и продолжение

- Новых токенов не создавали; history API использует существующий scope read.
  Настройка токена у TDM этим развёртыванием не проверялась.
- Массовую пересборку 2026, полную загрузку новых справочников, ручной запуск quality и
  обновление календарей не запускали; штатные задания продолжают работать.
- Неполнота источников, лицензии, рейтинги, ECB/Ratescalcs и другие открытые пункты ROADMAP
  этим релизом не закрываются. Данные не дополнялись вымышленными значениями.
- Полная изолированная репетиция install/rollback и browser UI-путь — остаток WEB-10.
  Production не откатывали для теста.
- Последующие опубликованные подписанные релизы предназначены для установки через Updates;
  push в main сам по себе не разворачивает приложение.
