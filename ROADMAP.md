## Как продолжить из другого инструмента

- Сначала читать этот файл, [разработку](docs/DEVELOPING.md), [deployment](deploy/README_DEPLOY.md)
  и [host-nginx схему](deploy/DOMAIN_DEPLOY.md). [STATUS](docs/STATUS.md) содержит исторические
  checkpoints, не актуальный список открытых работ; [SYSTEM_CONTEXT](docs/SYSTEM_CONTEXT.md)
  описывает отдельные обязательства перед Trading Desk Monitor, которые этот roadmap не отменяет.
- Production: `/opt/mdhub/current` → активный каталог в `/opt/mdhub/releases`;
  `/opt/mdhub/shared/compose.local.yaml` сохраняет host-nginx и loopback-порты при обновлении.
  PostgreSQL volume `mdhub_pgdata` содержит живые данные. Не запускать повторный seed restore.
- Публичны только TCP22/80/443; PostgreSQL5432/API8080/admin8081 слушают loopback.
  nginx направляет `/v1/` и `/health/` в API, остальное в admin. Не публиковать Docker-порты напрямую.
- Секреты получать только штатным защищённым способом. На Mac постоянное хранилище
  `~/.config/lima/secrets/`, на VPS конфигурация в `/root/.config/lima/secrets/market-data-hub/mdhub.env`.
  Не печатать значения, полный Compose config, auth-заголовки, cookies или enrollment URL.
  Закрытый ключ релизов на VPS не переносить. GitHub публичный: рабочие данные/дампы сюда не добавлять.
- Выпуск: tag → CI → code-only bundle → owner review/sign → verify → GitHub Release;
  затем админ выбирает версию в Updates. Это отдельный шаг от push/merge исходников.
- Перед изменением повторно проверить live-версию, активные задания, migration checksums и backup.
  После работы обновить checklist, факты/дату и ссылку на commit/релиз; незакрытое оставить открытым.
